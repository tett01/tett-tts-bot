# Discord TTS 봇 (edge-tts)

Microsoft Edge 신경망 음성을 쓰는 한국어/영어 디스코드 TTS 봇.
**완전 무료 · 무제한 · API 키 불필요.**

## 상태
- ✅ Python 버전: 설치·합성·ffmpeg 디코딩까지 **검증 완료** (권장)
- ⚪ Node.js 버전: 동일 기능을 discord.js로 옮긴 대안 (미검증)

## 빠른 시작 (Python)

```bash
brew install ffmpeg                    # 이미 설치됨
cd python-bot
cp .env.example .env                   # DISCORD_TOKEN 입력
.venv/bin/python bot.py
```

의존성은 `python-bot/.venv` 에 이미 설치되어 있습니다.
(새로 만들려면 `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`)

## 디스코드 설정 (한 번만)
1. [개발자 포털](https://discord.com/developers/applications) → New Application → Bot
2. **MESSAGE CONTENT INTENT 켜기** ← 안 켜면 채팅 내용이 안 와서 아무것도 못 읽습니다
3. Reset Token → 토큰 복사 → `python-bot/.env` 의 `DISCORD_TOKEN=` 에 붙여넣기
4. OAuth2 → URL Generator → scope `bot`
   권한: `Send Messages`, `Connect`, `Speak`, `Read Message History`, `Add Reactions`
5. 생성된 URL로 서버에 초대

## 명령어
| 명령어 | 동작 |
|---|---|
| `!join` `!들어와` | 내가 있는 음성 채널로 봇 호출 |
| `!leave` `!나가` | 봇 퇴장 |
| `!voice` `!목소리` | 목소리 목록 보기 / `!voice ava` 로 변경 |
| `!추임새 많이` `!chime` | 추임새 빈도 (끔/적게/보통/많이/항상) |
| `!say 내용` `!말해` | 직접 읽히기 |
| `!skip` `!넘겨` | 지금 읽는 문장 건너뛰기 |
| `!help` `!도움말` | 도움말 |

봇이 들어오면 **같은 음성 채널에 있는 사람의 채팅**을 자동으로 읽습니다.

## 목소리 프리셋

기본값은 **`yeonha`** 입니다.

edge-tts 음성에는 마이크로소프트가 붙인 용도 태그가 있습니다.
`ko-KR-SunHiNeural`은 **General(낭독·뉴스용)** 이라 또박또박한 아나운서 톤이고,
`AvaMultilingual`·`EmmaMultilingual`은 **Conversation + Copilot** 으로
음성 어시스턴트 대화용으로 튜닝돼 있어 훨씬 사람과 대화하는 느낌입니다.

| 프리셋 | 음성 | 특징 |
|---|---|---|
| `yeonha` **(기본)** | en-US-AvaMultilingual (+22Hz) | 밝고 어린 대화 톤. 추임새와 가장 잘 맞음 |
| `ava` | en-US-AvaMultilingual | 대화형. 표현력 풍부, 차분한 편 |
| `emma` | en-US-EmmaMultilingual | 대화형. 차분하고 따뜻한 구어체 |
| `sunhi` | ko-KR-SunHi (+8Hz, +10%) | 한국어 원어민. 발음 정확, 톤은 또박또박 |
| `news` | ko-KR-SunHi (보정 없음) | 원본 낭독조 |

### yeonha 톤 미세조정
`bot.py` 의 `PRESETS["yeonha"]` 에서 `pitch` 를 바꾸면 인상이 달라집니다.

| pitch | 느낌 |
|---|---|
| `+14Hz` | 차분한 편 |
| `+22Hz` | **현재 기본값** |
| `+30Hz` | 더 밝고 어림 |
| `+38Hz` | 애교 섞인 톤 (과하면 부자연스러움) |

`rate` 도 같이 올리면(+4% → +10%) 더 들뜬 느낌이 납니다.

**트레이드오프**: `ava`·`emma`는 대화 톤이 자연스럽지만 한국어 원어민 음성이
아니라서 받침·된소리에서 미세한 이질감이 있을 수 있습니다.
발음 정확도가 더 중요하면 `sunhi`를 쓰세요. `!voice` 로 즉시 바꿔가며 비교할 수 있습니다.

`samples/` 에 비교 샘플이 있습니다 (A=SunHi 기본 / B=Ava / C=Emma / D=Ava+전처리 / E=SunHi+전처리).

### SSML 감정 태그는 불가
`<mstts:express-as style="chat">` 같은 감정 스타일 태그는 edge-tts에서 막혀 있습니다.
태그를 감정으로 해석하지 않고 **글자 그대로 읽습니다** (테스트 결과 2.45초 → 6.91초).
조절 가능한 건 `rate`(속도)·`pitch`(음높이)·`volume` 뿐입니다.

## 자연스러움을 위한 텍스트 전처리

음성 선택만큼 중요한 게 입력 텍스트입니다. TTS는 문장부호를 억양·호흡 신호로
쓰기 때문에, 채팅 표기를 그대로 넣으면 어색해집니다. `humanize()` 가 자동 처리합니다.

| 입력 | 출력 |
|---|---|
| `야 근데 그 판 웃겼음ㅋㅋㅋ 다시 하자!!!` | `야, 근데 그 판 웃겼음, 하하, 다시 하자!` |
| `ㅇㅇ 나도 감ㅋㅋ ㄱㅅ~~~` | `응 나도 감, 하하, 고마워` |
| `ㅈㅅ 늦었어ㅠㅠㅠ` | `미안 늦었어` |

- `ㅋㅋㅋ`/`ㅎㅎㅎ` → 실제 웃음 ("크크크"로 읽히는 것 방지)
- 초성체 `ㅇㅇ ㄴㄴ ㄱㅅ ㅈㅅ ㅇㅋ ㄱㄱ ㅅㄱ ㅊㅋ` → 풀어서 읽기 (`ㄱㅅㄱㅅ` 처럼 반복해도 인식)
- `...` → 짧은 쉼 (긴 정적 방지), `!!!` → `!` (과장 억양 방지)
- 문두 접속사·감탄사 뒤 쉼표 삽입으로 사람의 호흡 재현
- `~`, `ㅠㅠ` 제거

규칙을 더하려면 `bot.py` 의 `humanize()` 를 수정하세요.

## 추임새 (연하봇 스타일)

메시지의 분위기를 읽고 앞뒤에 반응을 붙입니다. 추임새를 **본문과 같은 TTS 요청에
담기 때문에** 하나의 억양 흐름으로 이어져, 효과음을 따로 재생하는 것보다 자연스럽습니다.

```
야 어제 그 판 웃겼음ㅋㅋㅋ  →  푸흡, 야 어제 그 판 웃겼음, 하하, 아 배야
헐 대박!!!               →  우와, 헐 대박!
이거 어떻게 함??          →  음, 이거 어떻게 함, 그치?
야 나 망했어ㅠㅠ           →  아이고, 야 나 망했어
안녕~~                  →  아, 안녕, 반가워
ㄱㅅㄱㅅ                 →  아, 고마워, 별말씀을
```

### 분위기 8종
`laugh` `surprise` `question` `sad` `greeting` `agree` `thanks` `sorry` + `neutral`

분위기마다 앞 추임새(pre)와 뒤 반응(post) 목록이 따로 있고, 뚜렷한 분위기일수록
자주 붙습니다(인사 80% / 웃음 75% / 일반 28%).

실제 대화 로그로 측정한 전체 발동률은 **`보통` 기준 약 47%** 입니다.
(`적게` 24% / `많이` 71%). 일반 대화가 전체의 절반 가까이라 `neutral` 값이
체감 빈도를 좌우합니다 — 더 조절하려면 `chime.py` 의 `RATES["neutral"]` 을 보세요.

추임새를 매번 넣으면 금방 질리므로:

- **확률 기반** — 같은 말에도 붙을 때와 안 붙을 때가 있습니다
- **최근 6개 회피** — 같은 추임새가 연달아 나오지 않습니다
- **중복 차단** — "헐 대박"에 다시 "헐"을 붙이지 않습니다 (양방향 어절 검사)

### 빈도 조절
```
!추임새 끔 / 적게 / 보통 / 많이 / 항상
```
서버별로 따로 저장됩니다. 시끄러우면 `적게`, 아예 원문만 읽히려면 `끔`.

추임새 목록을 고치려면 `chime.py` 의 `CHIMES` 딕셔너리를,
분위기 판별 규칙은 `MOODS` 를 수정하세요.

## 텍스트 처리 파이프라인

읽을 문장은 3단계를 거칩니다 (`build_line()`). **순서가 중요합니다** — 추임새는
원문의 `ㅋㅋ`·`ㅠㅠ` 로 분위기를 읽으므로, `humanize()` 가 그 기호를 바꾸기
*전에* 붙여야 합니다.

```
1. strip_noise()  URL·멘션·이모지 제거      (기호는 남겨둠)
2. add_chime()    분위기 판별 → 추임새 삽입
3. humanize()     구어체 변환 + 문장부호 정리
```

## 동작 방식
- 한글이 한 글자라도 있으면 한국어 음성, 없으면 영어 음성으로 자동 전환
- 서버별 **재생 큐** — 여러 명이 동시에 쳐도 목소리가 겹치지 않고 순서대로
- URL은 "링크"로 치환, 멘션·채널 태그 제거, 커스텀 이모지는 이름만 읽음
- 200자 초과분은 잘라냄 (`MAX_CHARS`)
- 음성 채널에 봇만 남으면 자동 퇴장

## 디스호스트 배포

디스호스트는 셸 접속 없이 GUI 패널로 파일을 올리는 방식이라, `apt install ffmpeg`
같은 걸 할 수 없습니다. 그래서 `requirements.txt` 에 **`imageio-ffmpeg`** 를 넣어
ffmpeg 바이너리를 pip으로 함께 설치합니다. `resolve_ffmpeg()` 가 시스템 ffmpeg를
먼저 찾고, 없으면 번들 바이너리로 자동 전환합니다. (검증 완료)

### 업로드할 파일
```
bot.py             ← 스타트업 설정의 진입 파일로 지정
chime.py           ← 추임새 엔진 (없으면 import 오류)
requirements.txt
```
`check.py` 와 `.venv/` 는 올리지 않아도 됩니다.

### 토큰 설정
`.env` 파일을 올리는 대신 패널의 **환경변수(Secret)** 에 `DISCORD_TOKEN` 을
등록하세요. `os.getenv` 로 읽으므로 코드 수정이 필요 없습니다.
`.env` 는 절대 공개 저장소나 패널 공유 폴더에 올리지 마세요.

### 서버별 설정 유지
`settings.json` 이 봇 폴더에 자동 생성되어 서버별 목소리·추임새 설정을 보관합니다.
재시작해도 유지되며, 여러 서버에서 각각 다르게 맞춰 둘 수 있습니다.

### 호스팅 규칙 확인 필요
디스호스트는 **음악봇 호스팅을 금지**하고 있습니다. 이 봇은 외부 음원을
스트리밍하지 않고 텍스트를 합성해 재생하는 TTS 봇이라 성격이 다르지만,
규칙 해석은 운영진 권한이므로 **배포 전에 문의해 확인하시길 권합니다.**

## 여러 서버에서 함께 쓰기

서버별로 독립적으로 동작합니다.

- **재생 큐·재생 태스크**가 서버마다 따로 돌아 서로 밀리지 않습니다
- **목소리·추임새 설정**이 서버별로 저장됩니다 (`settings.json`)
- **추임새 중복 회피 기록**도 서버별로 분리됩니다
- 음성 연결은 재생할 때마다 새로 조회하므로, 채널 이동이나 재접속 후에도
  끊긴 연결을 붙들지 않습니다

edge-tts는 비공식 엔드포인트라 요청이 몰리면 일시 차단될 수 있어,
**동시 합성을 3건으로 제한**하고 실패 시 3회까지 재시도합니다.
서버가 늘어 끊김이 잦아지면 `bot.py` 의 `tts_lock` 값을 낮추세요.

## 알아둘 점
edge-tts는 Edge 브라우저의 비공식 엔드포인트를 사용합니다.
개인 서버용으로는 문제없지만, 호출이 과도하면 일시 차단될 수 있고
마이크로소프트가 언제든 막을 수 있습니다. 상업 서비스에는 부적합합니다.
