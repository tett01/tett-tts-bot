# 테트 TTS — 디스코드 한국어 TTS 봇

디스코드 음성 채널에서 채팅을 **사람처럼 자연스러운 목소리로** 읽어주는 봇입니다.
Microsoft Edge의 신경망 음성을 사용하며 **완전 무료 · 무제한 · API 키 불필요**입니다.

```
사용자: 야 어제 그 판 진짜 웃겼음ㅋㅋㅋ
   봇: "푸흡, 야 어제 그 판 진짜 웃겼음, 하하, 아 배야"
```

기계음이 아니라 대화하는 톤이고, 분위기를 읽어 추임새를 넣습니다.

## 빠른 시작

### 요구 사항

- Python 3.9 이상
- ffmpeg (없으면 `imageio-ffmpeg`가 자동 대체)
- libopus (음성 인코딩에 필수)

```bash
# macOS
brew install ffmpeg opus

# Ubuntu/Debian
sudo apt-get install ffmpeg libopus0
```

### 설치

```bash
git clone https://github.com/tett01/tett-tts-bot.git
cd tett-tts-bot/python-bot

python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

cp .env.example .env      # 토큰 입력
```

문제를 미리 잡아주는 스크립트가 있습니다. **먼저 이걸 돌리세요.**

## 디스코드 봇 설정

### 1. 애플리케이션 생성

[Discord Developer Portal](https://discord.com/developers/applications) → **New Application**

> 개발자 포털은 한국어 번역이 없습니다. 메뉴는 모두 영어로 표시됩니다.

### 2. 토큰 발급

**Bot** 탭 → **Reset Token** → 복사 → `.env`의 `DISCORD_TOKEN=`에 붙여넣기

토큰은 발급 화면에서 **한 번만** 보입니다. 절대 공유하지 마세요.

### 3. 인텐트 활성화 ⚠️ 필수

**Bot** 탭 → **Privileged Gateway Intents** → **MESSAGE CONTENT INTENT** 켜고 저장

이걸 안 켜면 봇이 접속은 되는데 **채팅 내용을 빈 문자열로 받아 아무것도 읽지 않습니다.**
조용히 실패하는 유형이라 원인을 찾기 어렵습니다.

### 4. 서버 초대

`YOUR_APPLICATION_ID`를 **General Information** 탭의 Application ID로 바꿔서 여세요:

```
https://discord.com/api/oauth2/authorize?client_id=YOUR_APPLICATION_ID&permissions=3214400&scope=bot%20applications.commands
```

`permissions=3214400`에 포함된 권한:

| 권한 | 용도 |
|---|---|
| 채널 보기 | 채팅 읽기 |
| 메시지 보내기 | 명령어 응답 |
| 메시지 기록 보기 | 메시지 수신 |
| 반응 추가 | `/skip` 의 ⏭️ 표시 |
| 음성 채널 접속 | 입장 |
| 말하기 | TTS 재생 |

관리자 권한은 포함하지 않았습니다.

## 명령어

슬래시(`/`)와 접두사(`!`) 둘 다 지원합니다.

| 명령어 | 별칭 | 동작 |
|---|---|---|
| `/설정` | `!설정` `!settings` | **설정 패널** — 목소리·추임새·자동입장을 한 화면에서 |
| `/join` | `!join` `!들어와` `!ㅈ` | 음성 채널로 호출 |
| `/leave` | `!leave` `!나가` `!ㄴ` | 내보내기 |
| `/voice` | `!voice` `!목소리` | 목소리 변경 |
| `/chime` | `!추임새` | 추임새 빈도 조절 |
| `/auto` | `!자동` | 자동 입장 켜기/끄기 |
| `/say` | `!say` `!말해` | 입력한 내용 읽히기 |
| `/skip` | `!skip` `!넘겨` | 현재 문장 건너뛰기 |
| `/help` | `!help` `!도움말` | 도움말 |

### 설정 패널

`/설정`을 치면 드롭다운과 버튼으로 즉시 바꿀 수 있습니다.

```
┌─ TTS 설정 ──────────────────────────
│ 목소리    yeonha
│           밝고 어린 대화 톤
│ 추임새    보통      자동 입장   켜짐
└─────────────────────────────────────
 [목소리 고르기       ▾]
 [추임새 빈도         ▾]
 [ 자동 입장 끄기 ]
```

선택 즉시 반영되고 `settings.json`에 저장됩니다. 조작 버튼은 2분 후 만료됩니다.

## 목소리 프리셋

기본값은 **`yeonha`** 입니다.

edge-tts 음성에는 Microsoft가 붙인 용도 태그가 있습니다. 이게 톤을 좌우합니다.

| 음성 | 카테고리 | 성격 |
|---|---|---|
| `ko-KR-SunHiNeural` | **General** (낭독·뉴스용) | Friendly, Positive |
| `en-US-AvaMultilingual` | **Conversation, Copilot** | Expressive, Caring, Friendly |
| `en-US-EmmaMultilingual` | **Conversation, Copilot** | Cheerful, **Conversational** |

`SunHi`는 아나운서 톤입니다. `Ava`·`Emma`는 **음성 어시스턴트 대화용으로 튜닝**된 음성이고 한국어도 발화합니다.

### 프리셋 목록

| 프리셋 | 음성 | 특징 |
|---|---|---|
| `yeonha` **(기본)** | Ava (+22Hz, +6%) | 밝고 어린 대화 톤. 추임새와 가장 잘 맞음 |
| `ava` | Ava (+2Hz, +3%) | 표현력 풍부, 차분한 편 |
| `emma` | Emma | 따뜻하고 차분한 구어체 |
| `sunhi` | SunHi (+8Hz, +10%) | 한국어 원어민. 발음 정확, 톤은 또박또박 |
| `news` | SunHi (보정 없음) | 원본 낭독조 |

**트레이드오프**: `yeonha`·`ava`·`emma`는 대화 톤이 자연스럽지만 한국어 원어민 음성이 아니라
받침·된소리에서 미세한 이질감이 있을 수 있습니다. 발음 정확도가 우선이면 `sunhi`를 쓰세요.

> `ko-KR` 여성 음성은 edge-tts에 **`SunHiNeural` 하나뿐**입니다.
> `JiMin`, `SeoHyeon` 등은 Azure 유료 전용이라 사용할 수 없습니다.

### 톤 미세조정

`bot.py`의 `PRESETS`에서 `pitch`·`rate`를 조정합니다.

| pitch | 느낌 |
|---|---|
| `+14Hz` | 차분한 편 |
| `+22Hz` | **기본값** |
| `+30Hz` | 더 밝고 어림 |
| `+38Hz` | 애교 섞인 톤 (과하면 부자연스러움) |

### SSML 감정 태그는 사용 불가

`<mstts:express-as style="chat">` 같은 감정 스타일 태그는 edge-tts에서 **차단**되어 있습니다.
감정으로 해석하지 않고 **글자 그대로 읽습니다** (테스트: 2.45초 → 6.91초).

조절 가능한 것은 `rate`(속도) · `pitch`(음높이) · `volume` 뿐입니다.
그래서 이 봇은 감정을 **텍스트 레벨**(추임새·문장부호)로 표현합니다.

## 추임새 시스템

메시지 분위기를 판별해 앞뒤에 반응을 붙입니다. 추임새를 **본문과 같은 TTS 요청에 담기 때문에**
하나의 억양 흐름으로 이어집니다. 효과음을 따로 재생하는 것보다 훨씬 자연스럽습니다.

```
야 어제 그 판 웃겼음ㅋㅋㅋ  →  푸흡, 야 어제 그 판 웃겼음, 하하, 아 배야
헐 대박!!!                →  우와, 헐 대박!
이거 어떻게 함??           →  음, 이거 어떻게 함, 그치?
야 나 망했어ㅠㅠ            →  아이고, 야 나 망했어
안녕~~                   →  아, 안녕, 반가워
ㄱㅅㄱㅅ                  →  아, 고마워, 별말씀을
```

### 분위기 8종

`laugh` · `surprise` · `question` · `sad` · `greeting` · `agree` · `thanks` · `sorry` + `neutral`

분위기가 뚜렷할수록 자주 붙습니다.

| 분위기 | 발동률 | 분위기 | 발동률 |
|---|---|---|---|
| 인사 | 80% | 감사·사과 | 70% |
| 웃음 | 75% | 슬픔 | 68% |
| 감탄 | 72% | 동의 | 58% |
| 질문 | 52% | **일반** | **28%** |

실제 대화 로그로 측정한 전체 발동률은 **`보통` 기준 약 47%** (`적게` 24% / `많이` 71%).

> 실제 대화의 **절반 가까이가 `neutral`** 이라, 이 값이 체감 빈도를 좌우합니다.
> 더 세밀하게 조절하려면 `chime.py`의 `RATES["neutral"]`을 보세요.

### 질리지 않게 만든 장치

- **확률 기반** — 같은 말에도 붙을 때와 안 붙을 때가 있음
- **최근 6개 회피** — 같은 추임새가 연달아 나오지 않음
- **중복 차단** — "헐 대박"에 다시 "헐"을 붙이지 않음 (어절 단위 양방향 검사)

### 조절

```
!추임새 끔 / 적게 / 보통 / 많이 / 항상
```

추임새 목록은 `chime.py`의 `CHIMES`, 판별 규칙은 `MOODS`, 빈도는 `RATES`에 있습니다.

## 텍스트 처리 파이프라인

읽을 문장은 3단계를 거칩니다 (`build_line()`).

```
1. strip_noise()   URL·멘션·이모지 제거      (기호는 남겨둠)
2. add_chime()     분위기 판별 → 추임새 삽입
3. humanize()      구어체 변환 + 문장부호 정리
```

**순서가 중요합니다.** 추임새는 원문의 `ㅋㅋ`·`ㅠㅠ`로 분위기를 읽으므로,
`humanize()`가 그 기호를 바꾸기 **전에** 붙여야 합니다.

### humanize() 변환 규칙

TTS는 문장부호를 억양·호흡 신호로 씁니다. 채팅 표기를 그대로 넣으면 어색해집니다.

| 입력 | 출력 | 이유 |
|---|---|---|
| `ㅋㅋㅋ` `ㅎㅎㅎ` | `하하` | 안 바꾸면 "크크크"로 읽음 |
| `...` | `,` | 부자연스러운 긴 정적 방지 |
| `!!!` | `!` | 과장된 억양 방지 |
| `ㄱㅅㄱㅅ` | `고마워` | 초성체 (반복형도 인식) |
| `ㅇㅇ` `ㄴㄴ` `ㅈㅅ` `ㅇㅋ` `ㄱㄱ` `ㅅㄱ` `ㅊㅋ` | 풀어서 읽기 | |
| `야 근데...` | `야, 근데...` | 문두 접속사 뒤 쉼표로 호흡 생성 |
| `~` `ㅠㅠ` | 제거 | |

`tidy()`가 마지막에 쉼표 중복·문두 쉼표·공백을 정리합니다.

## 자동 입장

음성 채널의 **내장 채팅창**에 글을 쓰면 봇이 알아서 들어와 읽습니다. 명령어가 필요 없습니다.

### 동작 조건

- 글쓴이가 **그 음성 채널에 실제로 접속**해 있어야 함
- 봇이 **다른 채널에서 사용 중이면 옮기지 않음** (쓰던 사람들을 방해하지 않기 위해)
- 그 채널이 비어 있으면 옮겨감
- 음성 채널에 아무도 없으면 3초 후 자동 퇴장

일반 텍스트 채널(`#일반` 등)에서는 동작하지 않습니다.
봇이 어느 음성 채널로 가야 할지 모호하기 때문입니다. 거기서는 `/join`으로 부르세요.

```
!자동 끔 / 켬
```

## 여러 서버에서 쓰기

서버별로 독립적으로 동작합니다.

- **재생 큐·재생 태스크**가 서버마다 따로 돌아 서로 밀리지 않음
- **설정**이 서버별로 `settings.json`에 저장됨
- **추임새 중복 회피 기록**도 서버별로 분리
- 음성 연결은 재생할 때마다 새로 조회하므로, 재접속 후에도 끊긴 연결을 붙들지 않음

edge-tts는 비공식 엔드포인트라 요청이 몰리면 일시 차단될 수 있어
**동시 합성을 3건으로 제한**하고 실패 시 3회 재시도합니다.
끊김이 잦으면 `bot.py`의 `tts_lock` 값을 낮추세요.

### 중복 실행 방지

같은 토큰으로 두 곳에서 실행하면 디스코드가 막지 않고 **양쪽 다 이벤트를 받습니다.**
같은 말을 두 번 읽고 음성 채널을 서로 뺏습니다.

파일 잠금으로 **같은 머신 안에서의** 중복은 차단합니다:

```
봇이 이미 다른 곳에서 실행중입니다.
  먼저 실행 중인 봇을 끄고 다시 시도하세요:  pkill -f bot.py
```

> **로컬 ↔ 호스팅 동시 실행은 코드로 막을 수 없습니다.** 서로의 존재를 알 방법이 없기 때문입니다.
> "한 곳에서만 켠다"는 운영 규칙으로 관리하세요.

## 디스호스트 배포

[디스호스트](https://dishost.kr/)는 셸 접속 없이 GUI 패널로 파일을 올리는 방식이라
`apt install` 같은 걸 할 수 없습니다. 그에 맞춰 대응해 두었습니다.

### 업로드할 파일

```
bot.py             ← 스타트업 설정의 진입 파일로 지정
chime.py           ← 빠뜨리면 import 오류로 즉시 죽음
requirements.txt
```

`check.py`와 `.venv/`는 올릴 필요 없습니다.

### 토큰 설정

**방법 A** — 패널에 환경변수 항목이 있으면 `DISCORD_TOKEN` 등록

**방법 B** — 없으면 파일 매니저에서 `.env` 파일 생성:

```
DISCORD_TOKEN=토큰
```

코드가 환경변수를 먼저 보고, 없으면 스크립트 폴더의 `.env`를 읽습니다.

### 정상 기동 로그


## 문제 해결

개발 중 실제로 겪은 문제들입니다.

### 봇이 음성 채널에 들어왔다 나갔다 반복

```
discord.errors.ConnectionClosed: WebSocket closed with 4017
```

**4017 = 알 수 없는 암호화 방식.** 디스코드가 음성 암호화를
`aead_xchacha20_poly1305_rtpsize`로 교체했는데 구버전 discord.py는 `xsalsa20_poly1305`만
지원합니다. **discord.py 2.7.1 이상**을 쓰세요.

### 봇은 들어오는데 소리가 안 남

```
[TTS 오류] OpusNotLoaded:
```

Opus 코덱을 못 찾은 경우입니다. 설치돼 있어도 `ctypes.util.find_library('opus')`가
Homebrew 경로(`/opt/homebrew/lib`)를 보지 않아 실패합니다.
`load_opus()`가 후보 경로를 직접 훑도록 해두었지만, 라이브러리 자체가 없으면:

```bash
brew install opus                    # macOS
sudo apt-get install libopus0        # Linux
```

호스팅 환경이면 운영진에 `libopus0` 설치를 문의하세요.

### 채팅을 전혀 읽지 않음

**MESSAGE CONTENT INTENT**가 꺼져 있습니다. 접속은 되지만 메시지 내용이 빈 문자열로 옵니다.

### 슬래시 명령어가 `/` 목록에 안 보임

디스코드 클라이언트가 캐시합니다. **⌘R**(Windows: **Ctrl+R**)로 새로고침하세요.

### 콘솔에 로그가 안 보임

파이썬이 출력을 버퍼링합니다. `sys.stdout.reconfigure(line_buffering=True)`로
해결해 두었습니다. 호스팅 콘솔에서 상태를 즉시 확인하려면 필수입니다.

### 슬래시 명령어가 오류남

```
NotFound: 404 (error code: 10062): Unknown interaction
```

슬래시 명령어는 **3초 안에 응답**해야 합니다. 음성 연결이 그보다 오래 걸리면 만료됩니다.
`/join`·`/leave`에 `ctx.defer()`를 넣어 해결했습니다.

### 대조표

| 증상 | 원인 | 해결 |
|---|---|---|
| 들어왔다 나갔다 반복 | discord.py 구버전 (4017) | 2.7.1 이상 |
| 들어오는데 무음 | Opus 미로드 | libopus 설치 |
| 채팅 안 읽음 | MESSAGE CONTENT INTENT | 포털에서 켜기 |
| `ModuleNotFoundError: chime` | `chime.py` 누락 | 함께 업로드 |
| `LoginFailure` | 토큰 오류 | 재발급 |
| 같은 말 두 번 읽음 | 중복 실행 | 한 곳만 켜기 |

## 기술 배경

### 왜 edge-tts인가

"평생 무료"가 조건이면 상용 API 무료 티어(월 1만 자 수준)는 디스코드 봇 트래픽에
며칠이면 소진됩니다. 남는 선택지는 **비공식 무료 엔드포인트**와 **로컬 오픈소스 모델**입니다.

| | 음질 | 한국어 | 감정 | 지연 | 비용 |
|---|---|---|---|---|---|
| **edge-tts** | ★★★★☆ | ★★★★☆ | ★★☆☆☆ | ★★★★★ | 무료·무제한 |
| Supertonic | ★★★★☆ | ★★★★★ | ★★★☆☆ | ★★★★★ | 무료 (로컬) |
| Chatterbox | ★★★★★ | ★★★☆☆ | ★★★★★ | ★★☆☆☆ | 무료 (GPU 필요) |

edge-tts는 Azure 상용 신경망 음성과 **같은 모델**을 키 없이 씁니다.
지연이 짧아 실시간 채팅 읽기에 적합합니다.

**단점**: 비공식 API입니다. Microsoft가 언제든 막을 수 있고, 과도한 호출 시 일시 차단될 수
있습니다. 개인·친구 서버용으로는 문제없지만 상업 서비스에는 부적합합니다.

더 나은 한국어 품질이나 진짜 감정 연기가 필요하면
[Supertonic](https://github.com/supertone-inc/supertonic)(한국어 원어민 모델, 로컬 실행)으로
교체하는 것이 유일한 무료 경로입니다.

## 프로젝트 구조

```
python-bot/
├── bot.py             메인 — 명령어, 재생 큐, 자동 입장, 설정 패널
├── chime.py           추임새 엔진 — 분위기 판별, 추임새 선택
├── check.py           실행 전 점검 스크립트
├── requirements.txt
└── .env.example

node-bot/              Node.js(discord.js) 버전 — 미검증 대안
samples/               음성 톤 비교 mp3
```

### 주요 함수

| 함수 | 역할 |
|---|---|
| `build_line()` | 텍스트 3단계 파이프라인 |
| `synthesize()` | edge-tts 합성 (동시 3건 제한, 3회 재시도) |
| `player()` | 서버별 재생 큐 처리 |
| `ensure_connected()` | 음성 연결 + 재생 태스크 기동 |
| `resolve_ffmpeg()` | ffmpeg 탐색 (시스템 → 번들 폴백) |
| `load_opus()` | Opus 코덱 경로 자동 탐색 |
| `chime.add_chime()` | 분위기 판별 → 추임새 삽입 |
